CHAPTER 05

从 Prompt 用户到 AI 系统设计者

AI 运用能力最终落到系统设计：把模型放进一个有数据、有工具、有评测、有权限、有成本约束的系统里，稳定解决真实问题。

第一层Prompt：说清楚任务。
中间层Context / RAG / Tool / Workflow：让模型接触真实世界。
高级层Agent / Eval / Guardrails：让系统可持续执行且可控。
运用层专家的核心能力把“模型能力”转化成“可重复的业务结果”。

很多 AI 项目失败在系统层：上下文不完整、数据接不上、输出不可验证、权限边界缺失、错误没人兜底，或者单位经济性根本不成立。

5.1 · PROMPT

Prompt：明确目标、约束和输出格式

Prompt 是最外层的人机接口。一个好 Prompt 通常至少包含：任务目标、背景、约束、示例、输出格式和质量标准。

目标到底要模型完成什么？
背景为什么要做，面向谁？
约束不能做什么，有什么限制？
格式最终输出必须长什么样？
Prompt 的边界

如果模型缺事实、缺文件、缺实时状态、缺工具权限，再好的 Prompt 也解决不了根本问题。

5.2 · CONTEXT ENGINEERING

Context Engineering：决定模型“此刻知道什么”

上下文工程关注整次任务执行：模型应该看到哪些系统规则、历史记录、文件、用户状态、工具结果和中间产物。

System角色、规则、边界、行为原则
User当前任务与真实意图
Memory相关历史、偏好和长期状态
Retrieval当前任务需要的外部知识
Tool Results实时搜索、数据库、计算和软件返回值

高手和普通用户的差距，往往体现在高质量上下文的组织能力上。

5.3 · RAG

RAG：不要让模型凭记忆猜，把相关资料先找出来

用户问题当前需求
→
检索从知识库找到相关内容
→
拼接上下文只给模型相关材料
→
生成回答基于检索内容作答

RAG 特别适合企业知识、政策、产品文档、内部资料等会变化或不能完全依赖模型参数记忆的场景。

RAG 的核心价值

把模型连接到企业自己的知识资产，同时提高信息的时效性和可追溯性。

5.4 · TOOL USE

Tool Use：模型不会的，不必都靠模型硬算

模型可以调用计算器、搜索、数据库、代码执行、邮件、日历、CRM、支付系统等工具。工具让 AI 从“语言生成器”变成“系统协调者”。

模型擅长

理解意图、生成语言、归纳、规划候选方案。

工具擅长

精确计算、实时数据、确定性操作、外部系统执行。

系统设计

决定什么时候该让模型想，什么时候该让工具做。

5.5 · WORKFLOW

Workflow：先把稳定流程自动化，再谈 Agent

如果一个任务步骤明确、分支有限、规则稳定，那么确定性 Workflow 通常比完全自由的 Agent 更可靠。

Step 1收集输入
→
Step 2分类 / 提取
→
Step 3调用数据库
→
Step 4生成结果
→
Step 5规则检查 / 人审
工程原则

能用固定流程解决，就不要因为“Agent 很酷”而引入额外不确定性。

5.6 · AGENT

Agent：当任务路径无法提前写死

Agent 适合目标明确、但完成路径需要动态选择的任务。它通常需要：目标、规划、工具、状态、观察、循环和退出条件。

Goal目标
→
Plan下一步做什么
→
Act调用工具
→
Observe读取结果
↺

Agent 的工程难点集中在长流程可靠性：减少跑偏和重复，限制越权，识别失败，并在正确时机终止。

5.7 · EVAL

Eval：没有评测，就没有“工程上的进步”

如果你只凭“感觉这次回答不错”来判断系统质量，就无法知道修改 Prompt、换模型或加 RAG 后到底有没有变好。

OFFLINE

离线评测

准备一组固定任务和标准，比较版本前后正确率、格式、事实性、延迟和成本。

ONLINE

在线评测

观察真实用户完成率、人工接管率、投诉、错误、转化、留存和单位成本。

成为专家的分水岭你不再问“哪个模型最好”，而问“哪个方案在我的 Eval 上最好”。
5.8 · GUARDRAILS

权限、安全与人类接管：能力越强，边界越重要

AI 一旦能操作外部系统，错误不再只是“回答错一句话”。因此要遵循最小权限、明确确认、高风险动作人审、日志记录和失败回滚。

最小权限

Agent 只获得完成当前任务真正需要的权限。

高风险确认

付款、删除、发送、发布等不可逆操作应设置明确确认。

可追踪

记录工具调用、输入输出和关键决策。

可中止

系统需要明确的超时、循环上限、异常退出和人工接管。

5.9 · ECONOMICS

成本：把最强模型留给真正需要它的步骤

一个成熟 AI 系统往往会做模型路由：简单分类交给便宜模型，复杂推理交给强模型，确定性计算交给工具，重复内容走缓存。

单位经济性

真正可规模化的 AI 产品，要同时优化正确率、延迟、Token、工具调用次数、人工接管率和用户价值。

5.10 · MATURITY LADDER

你的 AI 运用成熟度，可以这样分级

L0把 AI 当搜索框：想到什么问什么。
L1会写清晰 Prompt，控制格式和质量。
L2会组织文件、历史、上下文和检索。
L3会接 API、工具和固定 Workflow。
L4会做 Agent、状态管理、异常处理和 Eval。
L5会从业务结果、权限、成本和组织流程设计完整 AI 系统。

“AI 运用层专家”至少应该稳定站在 L4–L5，并掌握超越 Prompt 技巧的系统能力。

5.11 · LAB 05

把一个真实工作任务升级成 AI Workflow

选你每周都会做的一项工作，完成五步：

1 · 定义输入输出什么进来，什么叫完成？
2 · 补上下文模型必须知道哪些资料？
3 · 选工具哪些步骤应交给搜索、数据库、代码或外部 App？
4 · 建 Eval至少准备 10 个真实测试样本。
5 · 设边界什么动作需要人工确认？
