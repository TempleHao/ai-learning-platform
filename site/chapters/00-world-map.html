CHAPTER 00

AI 世界全地图

这一章先完成一件事：把整个 AI 世界的关键对象、相互关系和你当前所处的位置画清楚。

学完你应该能：用自己的话解释 AI / ML / DL / LLM / Agent / Robotics 的关系。
你不需要先会：高等数学、Python、神经网络公式或模型训练。
本章核心动作：建立“包含关系”和“系统关系”，以后所有新名词都往这张图上放。
先记住一句话

AI 是一个庞大的目标与技术集合：让机器完成过去需要人类智能才能完成的任务。模型和产品都只是这个集合里的具体实现。

初学 AI 最容易犯的错误，是把 ChatGPT、LLM、生成式 AI 和“人工智能”画上等号。实际上，今天最热门的大语言模型只是 AI 历史中的一条强势技术路线和一种重要产品形态。

你以后看到任何新名词，都先问三个问题：它属于技术方法、模型能力，还是产品/系统形态？它依赖什么？它解决什么问题？只要这三个问题能回答，热点就不会把你带乱。

0.1 · DEFINITION

AI 到底是什么？

NIST 对 AI 的定义之一，是一种机器系统：针对人类定义的目标，产生影响现实或虚拟环境的预测、建议或决策。这个定义有一个很重要的好处——它没有把 AI 限定为“像人一样聊天”。

判断 AI 能力，重点看完整能力链 感知 → 表示 → 学习 / 推理 → 决策 → 行动。

因此，垃圾邮件分类器、搜索排序、自动驾驶感知系统、围棋程序、语音识别、推荐系统、大语言模型和机器人，都可以属于 AI。它们“智能”的表现完全不同。

0.2 · HIERARCHY

先画严格的包含关系，再辨认交叉分类

这张图只展示方法上的包含关系：AI ⊃ ML ⊃ DL。传统规则系统可以属于 AI，但未必使用机器学习；梯度提升树属于机器学习，通常不属于深度学习。

Artificial Intelligence · AI最大集合：让机器表现出智能能力
Machine Learning · ML让系统从数据中学习规律，减少对手工规则的依赖
Deep Learning · DL以多层神经网络为核心的一大类机器学习方法；大多数当代基础模型与 LLM 使用深度学习。
另一条分类轴：基础模型与语言模型

Foundation Model（基础模型）强调广泛数据上的预训练，以及适配多种下游任务的能力；Stanford CRFM 于 2021 年提出这一用法。LLM（大语言模型）强调以语言或 Token 序列为主要建模对象及其规模。很多 LLM 同时是基础模型，但“基础模型”还包括视觉、语音及多模态模型；两者的名称回答不同问题，不能把所有深度学习模型都归为基础模型。

系统与能力也有各自的分类轴

RAG 是检索增强的应用架构；Agent 是围绕目标进行观察、决策与行动的系统设计；Multimodal 描述处理多种模态的能力；Reasoning 描述推理能力或过程；Robotics 涉及感知、控制、执行器与物理环境。它们可以组合，例如一个机器人系统可能调用多模态基础模型，也可能完全不使用 LLM。

0.2A · DIAGNOSTIC PRACTICE

四个案例：先识别对象，再画依赖关系

用三个问题判断：①它是模型、方法、能力还是系统？②它依赖哪些部件？③名称之间是包含、交叉还是调用关系？先独立写下答案，再展开解析。

案例 A：银行用梯度提升树预测商户拒付风险。它一定属于深度学习吗？

这是机器学习模型，梯度提升树通常属于非深度学习方法。模型输出风险分数；业务系统还需设置阈值、人工复核和申诉流程。ML ⊂ AI 成立，DL 标签在此不适用。

案例 B：一个经过广泛预训练、可完成翻译与摘要的大语言模型。它有几个标签？

通常同时属于 ML、DL、LLM，并符合基础模型的广泛预训练与可适配特征。LLM 描述语言建模类别；Foundation Model 描述预训练与迁移用途。实际分类应核对模型训练和适配证据。

案例 C：客服系统先检索订单，再让 LLM 起草回复，最后等待人工审批。它属于什么？

整体属于 AI 应用系统，包含检索增强流程、模型调用与人工控制。检索并不自动等于模型训练；人工审批使最终行动受权限约束。系统使用 LLM，不代表系统本身是一种 LLM。

案例 D：机械臂通过摄像头定位包裹，再用控制器完成抓取。它一定需要 LLM 吗？

这是机器人系统，涉及视觉感知、控制和物理执行。它可能采用传统算法或学习模型，是否使用 LLM 取决于具体架构。应分别评估感知准确率、抓取成功率和安全边界。

验收标准 · 约 12 分钟

任选两例，分别写出对象类别、至少两个依赖部件及一个不能由名称直接推出的结论。再为案例 C 画出“订单检索 → LLM 草稿 → 人工审批 → 发送”的流程，并指出哪个环节决定是否真正发送。能独立解释因果关系后，再进入下一节。

0.3 · SYSTEM THINKING

把“模型”和“AI 产品”分开，是成为运用层专家的第一步

用户体验层聊天界面 · IDE · 企业软件 · 机器人 · 工作流
Agent / 应用层任务拆解 · 记忆 · 权限 · 工具调用 · RAG · 工作流
模型层LLM · Vision · Speech · Embedding · Reward / World Model
训练与数据层预训练 · 后训练 · 数据 · 评测 · 人类反馈
计算基础层GPU / Accelerator · HBM · 网络 · 数据中心 · 电力

很多商业误判都来自把“模型能力”当成“产品价值”。一个模型即使能力很强，也不意味着企业会直接得到价值。真正落地时还需要数据接入、权限、流程设计、可靠性、评测、成本控制和用户界面。

商业视角

模型越强，某些应用层功能会被模型原生能力“吞掉”；但同时，更强模型也会让以前不可行的新工作流变得可行。机会往往出现在这两个力量之间。

0.4 · CAPABILITY MAP

AI 的能力沿多条分支扩展，形成一张“能力树”

Perception

感知

视觉、语音、传感器，让机器把现实世界转化为可处理的信息。

Language

语言

理解、生成、翻译、总结、对话和结构化表达。

Prediction

预测

分类、排序、推荐、风险评分、时间序列和需求预测。

Generation

生成

文本、图像、音频、视频、3D、代码以及其他数字内容。

Reasoning

推理与规划

多步问题、数学、代码、搜索策略、计划与决策。

Action

行动

调用软件工具、操作电脑、执行工作流，最终进入物理世界。

从应用角度看，能力链的延长比单个榜单分数更值得关注：过去 AI 多数只负责预测一个答案，今天越来越多系统开始理解任务 → 规划 → 调工具 → 检查结果 → 继续行动。

0.5 · HISTORY IN ONE PAGE

先看一条极简历史线，后面再展开技术路线战争

1950s“机器能否思考？”成为正式科学问题；1956 年 Dartmouth 会议确立 Artificial Intelligence 这一研究领域。
1960s–1980s符号主义、搜索、专家系统占据重要位置：知识和规则主要由人写进去。
1990s–2000s统计机器学习壮大：从“写规则”逐渐转向“从数据里学规律”。
2010s算力、数据与深度神经网络结合，视觉、语音等领域出现突破。
2017Transformer 提出，用注意力机制重构序列建模方式，后来成为大语言模型的关键基础。
2020s基础模型与生成式 AI 普及；能力从内容生成扩展到推理、工具使用、Agent 与多模态交互。

每次范式变化都围绕几组核心选择展开：规则由人编写还是从数据中学习？专用系统还是通用模型？只输出答案还是拥有行动能力？ 年份只是这些选择发生转折的坐标。

0.6 · FRONTIER SNAPSHOT · 2026

今天我们站在哪里？

以下是 Stanford HAI《2026 AI Index》对 2025 年及此前研究与调查的汇总，核验于 2026-10-31。OSWorld、家庭机器人任务与组织调查的样本和指标各不相同；它们可用来提出研究问题，不能相互作性能比较。

66.3%OSWorld 计算机操作基准上的 Agent 任务成功率（2025 年报告数据）评测集上的任务成功率；约三分之一任务仍失败，不能直接外推到任意生产工作流。
12%报告所引真实家庭机器人任务的成功率任务、环境和评分口径不同于 OSWorld；两个百分比不能直接当作同一能力的排名。
88%受调查组织报告至少一项业务职能使用 AI 的比例（2025 年）属于组织采用率，不能说明有 88% 的工作流程已实现自动化。
你应该形成的判断

2026 年的主线已经转向系统能力：模型能否可靠推理、使用工具、持续执行任务，并进入企业流程与物理世界。

0.7 · MISCONCEPTIONS

七个必须尽早纠正的误区

误区 1：AI = ChatGPT

ChatGPT 是 AI 产品；LLM 是其核心模型技术之一；AI 的范围远大于两者。

误区 2：大模型就是数据库

模型参数无法像事实表一样逐条查询。训练形成的是统计表示，因此模型可能“会说但说错”。

误区 3：参数越多一定越聪明

规模很重要，但数据、训练方法、架构、后训练、工具、推理策略和评测同样重要。

误区 4：Benchmark 高 = 工作中一定好用

真实工作还有上下文、权限、流程、可靠性、成本、延迟和异常处理。

误区 5：Agent 就是会自动回复的机器人

Agent 的关键是围绕目标持续选择行动、调用工具、观察结果并继续执行。

误区 6：AI 进步是匀速的

不同能力发展极不均衡，会出现“数学很强但简单感知任务很差”的锯齿状前沿。

误区 7：懂 AI 就必须先学会训练模型

对运用层专家而言，更重要的是理解能力、系统结构、数据、评测、经济性和边界。

0.8 · LAB 00

第一个练习：给所有 AI 名词“找位置”

接下来一周，遇到一个 AI 新名词，先查清它描述的对象和证据，再把它放进下面四个抽屉中的一个或多个。多个标签可以同时成立：

A · 技术方法如 Transformer、强化学习、蒸馏
B · 模型/能力如 LLM、Foundation Model、Vision Model、Reasoning（需注明是模型类别还是能力）
C · 系统架构如 RAG、Agent、Memory、Tool Use
D · 产品/产业如 Copilot、机器人、AI 搜索、垂直 SaaS
0.9 · SELF CHECK

本章自测：检查你的 AI 世界地图是否已经建立

Q1：为什么“LLM ⊂ AI”成立，而“Agent ⊂ LLM”不成立？

LLM 是 AI 模型的一类；Agent 是可调用模型与工具的系统设计。一个 Agent 可以使用 LLM，调用关系无法推导为包含关系。先区分对象层级，再判断是否存在模型依赖。

Q2：为什么模型能力提升不会自动转化为商业价值？

真实价值还取决于数据接入、工作流、权限、安全、可靠性、成本、分发和组织变革。模型只是系统的一层。

Q3：OSWorld 的 66.3% 与家庭机器人任务的 12% 能直接证明数字 Agent 比机器人“聪明”吗？

不能。两项评测的任务、环境、样本和成功标准不同。应分别检查各自的基准定义、失败案例与目标应用环境，再讨论可靠性。

Q4：基础模型与大语言模型的分类依据有何区别？

基础模型关注广泛预训练与下游任务适配；LLM 关注语言或 Token 序列建模及规模。一个模型可能同时符合两种分类；具体结论需要训练方式和用途的证据。
