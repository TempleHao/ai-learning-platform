DEEP DIVE 05

AI-native Organization

“AI 会不会取代这个岗位？”通常问错了。更好的问题是：这个岗位由哪些任务组成？哪些任务可以自动化、哪些只能增强、哪些必须保留人的判断与责任？

组织视角把岗位拆成任务，再设计人、Workflow、Agent 的边界。
管理视角理解 Agent 如何改变管理半径、异常处理和绩效衡量。
个人视角知道哪些能力因为 AI 更值钱，而不是只问“什么工作会消失”。
先改变分析单位

岗位不是一个原子。一个岗位通常同时包含重复执行、信息整理、判断、沟通、关系、创意、责任和异常处理。AI 对这些任务的影响速度并不一样。

D5.1 · EXPOSURE ≠ REPLACEMENT

“这个岗位暴露于 AI”不等于“这个岗位会消失”

ILO 2025 年的全球研究把分析做到了接近 3 万项职业任务，结论之一是：全球约四分之一劳动者所在职业对生成式 AI 存在某种程度的暴露，但由于大量任务仍需要人类输入，最可能发生的是工作内容转型，而不是岗位整体自动消失。

AUTOMATION

任务被自动完成

重复、标准化、结果容易验收的任务最先进入这一区域。

AUGMENTATION

人 + AI 共同完成

AI 做草稿、检索、分析，人负责判断、沟通、责任与例外。

因此，未来的就业冲击更可能首先表现为：岗位内部任务占比变化、入门岗位减少、一个人管理更多产出，以及某些岗位的招聘需求下降，而不是所有职业同时消失。

D5.2 · TASK ALLOCATION

人和 AI 的分工，取决于六个变量

结构化程度输入、步骤和输出是否相对稳定？
可验收程度机器能否判断结果“对不对”？
错误代价错一次是多花十分钟，还是造成法律 / 财务 / 安全后果？
异常率标准流程之外的长尾情况有多少？
隐性知识是否依赖关系、组织政治、经验或难以写下来的判断？
系统接入AI 是否真的能访问所需数据和工具？
基本原则越结构化、越可验收、错误越可逆、系统接入越完整，就越适合把执行权交给 AI。
D5.3 · INTERACTIVE DELEGATION MATRIX

这个任务该给 Copilot、Workflow、Agent，还是人？

拖动下面六个变量。它不是“自动化真理”，而是强迫你把直觉拆成明确条件。

RECOMMENDED MODE Copilot + Human 50 / 100

D5.4 · MANAGEMENT SPAN

Agent 可能首先改变“一个人能管理多少工作”，而不是直接改变职位名称

当标准执行步骤可以交给 Agent，人的工作会更像：定义目标、分配任务、审查结果、处理异常、决定高风险动作。管理半径因此可能扩大。

TRADITIONAL1 位经理 → 多名执行人员 → 软件工具
→
AI-AUGMENTED1 位专家 → AI Copilot + 更少重复执行
→
AGENT-NATIVE1 位负责人 → 多个数字执行单元 + 少量异常处理
组织指标也要变化

如果人不再亲自完成每一步，绩效不能只看“工作时长”或“处理量”，而要看目标设定质量、Agent 成功率、异常率、错误损失和最终业务结果。

D5.5 · THE JUNIOR-LADDER PROBLEM

最棘手的问题之一：如果 AI 先吃掉初级任务，人靠什么成长成高级专家？

很多职业的学习路径依赖“先做大量低风险、重复但能积累模式识别的工作”。如果这些任务被 AI 自动完成，企业短期效率可能提高，但长期可能削弱人才梯队。

01

旧学徒制

新人通过大量基础任务获得情境和错误经验。

02

AI 先做第一遍

新人直接面对更复杂任务，却可能缺少底层经验。

03

新训练机制

企业需要刻意设计复盘、模拟、审阅与轮岗，而不能只追求自动化率。

04

新的入门价值

初级员工可能从“做产出”转向“检查 AI、整理 Context、构建 Eval、处理例外”。

Stanford AI Index 2026 报告中，部分 AI 暴露较高职业的年轻员工已经出现更明显的就业变化，例如 22–25 岁软件开发者的就业从 2024 年起明显下降；但整体劳动市场并没有出现同等规模的普遍失业。这种不均衡非常值得持续跟踪。

D5.6 · NEW ROLES

AI-native 组织会出现一批“连接模型与业务”的角色

WORKFLOW

AI Workflow Architect

把业务流程拆成 Context、模型、工具、规则、审批和 Eval。

核心：流程与系统设计。
OPS

Agent Operator

管理 Agent 任务队列、异常、失败恢复、成本和权限。

核心：运行与例外管理。
EVAL

Eval / Quality Engineer

构建测试集、评分器、回归评测和生产监控。

核心：可测量的质量。
DOMAIN

Domain Reviewer

把专业责任留在人类专家手里，重点审查高风险输出。

核心：责任与专业判断。
PRODUCT

AI Product Owner

决定哪些任务值得自动化、价值在哪里、成功标准是什么。

核心：价值与取舍。
GOVERNANCE

AI Governance / Control

制定权限、模型准入、数据边界、审计和风险政策。

核心：制度与控制面。
D5.7 · RESPONSIBILITY

组织设计的核心不是“谁用了 AI”，而是“谁对结果负责”

OWNER任务所有者

谁定义业务目标和完成标准？

OPERATOR运行者

谁监控 Agent、处理异常、管理预算？

APPROVER审批者

高风险动作由谁确认？

ACCOUNTABLE责任人

系统出错造成损失后，谁承担最终责任？

当 Agent 跨多个系统执行任务时，传统“一个软件、一个用户、一个操作记录”的责任模型会变复杂。企业必须把身份、授权、审批、审计和责任映射到 Agent 运行链上。

D5.8 · PROCUREMENT + PRICING

AI-native 组织会反过来改变企业软件采购

如果一个 Agent 可以替多人执行标准流程，传统按 Seat 收费会越来越难完整表达价值。采购部门可能开始比较：

Seat Cost每个用户多少钱
→
Task Cost每个任务多少钱
→
Outcome Cost每个结果多少钱
→
Total Labor Cost与人工 / 外包一起比较

这意味着软件供应商会越来越需要证明“每个完成任务的完全成本”和实际业务结果，而不是只证明用户登录了多少次。

D5.9 · TRANSITION PATH

企业不会一夜之间变成 Agent-native，更可能经历四个阶段

PHASE 1

个人工具化

员工自行使用 Chat / Copilot，提高局部效率。

风险：影子 AI、数据边界模糊。
PHASE 2

团队 Workflow

高频任务形成标准 Prompt、RAG、工具和 Eval。

目标：可复用和可测量。
PHASE 3

Agent 托管部分流程

标准任务由 Agent 执行，人处理例外和审批。

目标：单位任务成本下降。
PHASE 4

组织重构

岗位、软件、预算与管理方式围绕“人 + 数字执行单元”重新设计。

目标：业务模型变化。
D5.10 · FRONTIER SNAPSHOT · 2026

当前证据更支持“任务结构变化”，而不是“已经发生全面岗位替代”

1 / 4全球劳动者所在职业对 GenAI 有一定暴露ILO 认为转型比整体替代更可能。
32%组织预计未来一年 AI 会减少员工规模但约 43% 预计几乎没有变化，现实仍高度分化。
88%受访组织报告已经使用 AI采用很广，但 Agent 在多数业务职能仍处个位数部署。

这说明 2026 年仍是一个“能力和采用跑在组织设计前面”的阶段。企业已经普遍使用 AI，但真正把岗位、责任、预算和软件采购围绕 Agent 重构，仍处在非常早期。

D5.11 · PERSONAL SKILLS

对个人来说，AI 时代最稀缺的能力可能从“执行步骤”迁移到五类能力

01

问题定义

知道真正要解决什么，而不是只会接受任务。

02

任务分解

把目标拆成模型、工具、规则和人可以协作的模块。

03

Context 构建

给 AI 正确资料、状态、约束和示例。

04

Eval 与判断

能分辨“看起来不错”和“真的完成任务”。

05

责任与关系

沟通、信任、谈判、承担后果和处理例外仍高度人类化。

D5.12 · ORGANIZATIONAL RISKS

高自动化组织也有新的脆弱性

SKILL

技能空心化

人失去基础实践机会，出现“会审 AI 但不会自己做”的脆弱性。

CONCENTRATION

关键人集中

少数高级人员管理大量 Agent，错误决策的影响半径放大。

MEASUREMENT

指标异化

为了追求自动化率而把不适合的任务强行 Agent 化。

POWER

权力重分配

掌握模型、数据和控制面的人拥有更大组织权力。

VENDOR

供应商锁定

流程越来越依赖某个模型、云或 Agent 平台。

RESPONSIBILITY

责任模糊

“AI 做的”可能成为规避责任的借口。

D5.13 · SELF CHECK

本页自测

为什么应该分析任务，而不是直接分析岗位？

因为同一岗位内部包含自动化难度完全不同的任务。AI 可能自动化其中一部分、增强另一部分，同时保留需要关系、责任和异常判断的部分。

什么任务最适合 Agent 化？

目标清晰、路径有不确定性、结果可验收、错误可恢复、系统接入完善，而且单位经济性成立的任务。

为什么初级岗位自动化可能产生长期组织问题？

很多高级能力来自早期基础工作积累。如果低级任务全部被 AI 吃掉，企业需要重新设计训练、复盘和人才成长路径。

AI-native Organization 最关键的新管理能力是什么？

目标定义、任务分解、Context、Eval、异常管理、权限控制和责任设计。
