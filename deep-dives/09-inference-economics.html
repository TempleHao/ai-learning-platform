DEEP DIVE 09

Inference Economics
与 Model Routing

AI 产品进入生产阶段后，模型能力只是一个变量。系统要在质量门槛、响应时间、风险边界和单位任务成本之间找到可持续组合。

工程拆解 TTFT、尾延迟、Token、缓存与异步处理对体验和成本的影响。
决策用 Eval 建立模型准入门槛，再用规则、分类器和级联策略分配请求。
商业把 API 账单连接到成功任务成本、毛利率、人工接管和错误损失。
核心判断

生产系统应选择“通过任务质量门槛的最低总成本路径”。总成本包含模型、工具、基础设施、人工复核、重试与错误损失。

D9.1 · COST PER TASK

API 单价只是成本表的第一行

TOTAL VARIABLE COSTC_task = Σ(模型输入 + 缓存输入 + 模型输出) + 工具 + 基础设施 + 人工复核 + 预期错误成本
调用结构一个用户动作可能触发规划、检索、生成、验证和重试等多次调用。
成功口径便宜但失败率高的路径会增加返工。应计算每个“被接受任务”的成本。
尾部任务平均值会掩盖长上下文、超长输出和异常循环。P95 往往更接近真实风险。
D9.2 · QUALITY GATE + SLO

先定义可接受，再讨论便宜

QUALITY GATE

任务级 Eval

用真实任务集测正确性、格式、引用、工具结果、拒答和安全边界。每类任务可以拥有不同门槛。

  • 小模型达到门槛即可进入候选
  • 风险越高，门槛和验证越严格
  • 路由策略变化必须跑回归测试
LATENCY SLO

用户体验预算

同时观察首 Token 时间、完整完成时间与 P95 / P99。流式输出可以改善感知速度，却不会缩短后台真实完成时间。

  • 实时交互关注 TTFT 与 P95
  • 离线任务允许换取更低成本
  • 工具链延迟需单独分解
D9.3 · ROUTING LADDER

路由成熟度从固定分工走向可验证的动态升级

01 静态分工按功能固定模型，易解释、易调试。
02 规则路由依据长度、模态、风险、语言和时限。
03 分类器预测任务难度或最合适的模型档位。
04 级联升级低成本路径先跑，未通过验证再升级。
05 高价值双检生成器与检查器分离，必要时人工审批。
路由陷阱

“模型自评信心”不能直接当作可靠路由信号。应结合可观测特征、外部验证器、任务风险和历史 Eval 校准。

D9.4 · TOKEN ECONOMICS

上下文设计同时影响质量、延迟和账单

输入 Token系统指令、工具定义、历史消息、检索片段和文件都会反复进入请求。
输出 Token输出通常更贵；限制冗余、使用结构化输出可直接降低成本和等待时间。
推理预算复杂任务可提高推理强度，简单任务应限制额外计算。
Context Growth长会话需要摘要、压缩或外部状态，避免每轮完整重放。
D9.5 · DELIVERY MODES

把任务的“时间价值”纳入系统设计

CACHE

复用稳定前缀

保持系统指令、工具定义和固定资料前缀稳定，可减少重复计算。监控命中率，避免前缀轻微变化导致缓存失效。

BATCH

聚合离线请求

Eval、批量分类、Embedding、离线抽取适合异步批处理。用户不等待的任务无需购买实时性。

FLEX / ASYNC

用时间换成本

低优先级服务档位和后台任务适合容忍更慢响应的工作。前台应返回清晰状态与恢复路径。

OpenAI 当前官方文档把 Batch、Flex、Prompt Caching 与减少请求 / Token 并列为成本优化路径。具体折扣、支持模型和限制会变化，实施时应以供应商最新文档为准。

D9.6 · UNIT ECONOMICS

从“单次调用”上升到“每个成功任务”

ACCEPTED TASK ECONOMICS每个成功任务成本 = 总可变成本 ÷ 被接受任务数　｜　毛利率 =（收入 − 可变成本）÷ 收入
升级率反映低成本路径覆盖能力。持续过高需要重做分工或首选模型。
人工接管率是质量与成本的共同信号，不能从 AI 账单中漏掉。
错误损失退款、客户流失、合规事件和错误决策会放大“便宜模型”的真实代价。

D9.8 · OBSERVABILITY

路由系统需要一张可以解释决策的账

质量任务成功率、人工评分、拒答、引用正确率、回归测试。
延迟TTFT、完整时长、工具时长、P50 / P95 / P99。
成本输入 / 缓存 / 输出 Token、调用次数、工具与人工成本。
路由模型分布、升级率、缓存命中率、Batch 覆盖率、回退原因。

日志必须保留任务类型、路由原因、模型版本、Prompt 版本和 Eval 结果。缺少这些字段时，成本波动和质量回归很难追溯。

D9.9 · LAB 11

为一个真实 AI 应用建立模型路由与成本基准

验收标准

交付路由规则、50+ 任务 Eval、成本表、延迟分布、失败案例和明确决策。成本下降必须保持质量门槛与风险边界。

D9.10 · SELF CHECK

本页自测

为什么不能只比较模型的 Token 单价？

总成本还受调用次数、上下文长度、输出长度、工具、重试、人工接管与错误损失影响。产品需要比较每个成功任务的成本。

模型路由为什么必须建立在 Eval 之上？

路由的目标是在质量门槛内优化成本和延迟。缺少真实任务 Eval 时，系统无法知道低成本路径是否已经突破质量边界。

Cache、Batch 和流式输出分别解决什么问题？

Cache 复用重复前缀；Batch 用等待时间换成本和吞吐；流式输出改善首段响应体验。三者处理的瓶颈不同。

什么时候应该直接选择更强模型？

高影响、难验证、失败代价高的任务，以及低成本路径频繁升级或返工的任务，通常适合更强模型并配合独立验证。
